About This Guide 
This guide provides a curated list of optional external resources that students may explore when 
planning, designing, implementing, testing, documenting, or presenting a CCIT4080 project. The 
resources are suggestions only. A group should choose tools because they suit the engineering 
problem, not because they appear in this guide. 
 
CCIT4080 projects may be hardware-focused, software-focused, integrated hardware-software 
systems, simulation-oriented, or research-informed development projects. A functional prototype 
remains the central goal, so the most useful resource will depend on the project scope and the 
evidence the group needs to produce. 
 
AI-generation notice 
This document was generated entirely using generative AI and received only limited manual 
checking for obvious errors, duplication, course relevance, and readability. Service names, 
eligibility requirements, quotas, interfaces, licence conditions, and free-tier limits can change. 
Students should always verify the current information on the official provider website before 
relying on a service. 
 
GitHub Student Developer Pack as the starting point 
The GitHub Student Developer Pack is included as the first resource in this guide because it 
provides one convenient gateway to many student benefits. Individual services already offered 
through the Pack - for example, Azure, JetBrains, Notion, MongoDB, Arduino, Deepnote, Heroku 
and other Pack partners - are generally not duplicated as separate entries below. The remaining 
resources are intended to complement the Pack.  GitHub Student Developer Pack 
 
Before signing up 
⚫ 
Use an official provider website. Avoid unofficial download pages or third-party licence 
sellers. 
⚫ 
Prepare your College student email and proof of current student status when an education plan 
requires verification. 
⚫ 
Read the educational-use, non-commercial-use, public-project, storage, quota, and renewal 
conditions before starting important project work. 
⚫ 
Do not enter payment-card details or upgrade to a paid plan unless the group deliberately 
decides that a paid service is necessary. 
⚫ 
Do not upload confidential, personal, copyrighted, or sensitive project data to an external 
service without considering privacy and licence implications. 
⚫ 
When an AI tool or AI-generated output is used in assessed work, follow the current 
CCIT4080 instructions on declaration, documentation, and academic honesty.

Final Reminder - Use the Resource, Do Not Let the Resource Define the Project 
A CCIT4080 project should begin with a problem, objectives, requirements, engineering decisions, 
implementation and testing. A free tool is useful only when it helps the group carry out those steps 
more effectively. 
 
Free does not always mean unrestricted 
Education licences may be limited to non-commercial use; cloud tiers may have quotas; free 
projects may be public; student editions may limit model size, export, file compatibility, or 
collaboration; and eligibility may need to be renewed. Keep project files backed up in formats 
that can be moved to another tool if necessary. 
 
A sensible selection process 
⚫ 
Start with the project requirements and identify the specific task that needs a tool. 
⚫ 
Compare two or more approaches when the tool choice affects architecture, performance, cost, 
privacy, maintainability, or project risk. 
⚫ 
Prefer tools the group can explain and use independently rather than tools that merely produce 
attractive outputs. 
⚫ 
Record important versions, settings, assumptions and licences in the Logbook or technical 
documentation when they affect reproducibility. 
⚫ 
Keep original source files, raw data, test evidence and exportable backups throughout the 
project. 
⚫ 
For assessed work, explain what the group actually designed, implemented and tested. A 
commercial or AI-assisted tool does not substitute for engineering evidence.
